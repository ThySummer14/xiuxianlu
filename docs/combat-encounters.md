# 山魈与猎妖见闻

## 第一批内容

本批给山魈加入一个有明确应对方式的机制，并用两段关联事件连接备战、实战和复命。狐妖、蛇妖、蛛妖仍保留原本行为；没有声称四类敌人已全部重做。

- 第6层安排首次山魈，其后保留既有确定性种类分布。第40层是原分布中首次山魈首领。
- 山魈保留前两次普通攻击；第三次不立即命中，而是举拳蓄势3.2秒。原生HUD显示倒计时、进度条、破招命中数与归山选项提示。
- 蓄力期间3次有效手动挥剑可打断。按住连斩也有效；相邻计数至少0.22秒，自动剑侍伤害不算手动命中。测试以0.5秒间隔完成，未要求高速点击。
- 破招后1.5秒不能攻击，受到伤害×1.2。未打断时重击为普通攻击×1.6，且至多扣最大气血35%。这是替换第三击并增加前摇，不是额外叠加攻击。
- 归山可随时保留已有血量。切后台、长帧停顿和重载都不会在看不见画面时结算重击。关闭遮挡战斗的弹窗后，蓄力重新给足完整提示时间。

## 有后续的选择

魔窟面板下方「猎妖见闻」在到达第6层后开放，不强制弹窗打断战斗。

1. 山道猎妖人：选2张护山符，或立即参悟一部有效功法最多6点领悟。预览显示实际功法与点数；功法皆满悟时转为有上限的修为，避免老玩家白选。
2. 亲手成功破招后复命：选剑心+1的永久挥剑收益，或将护符补满到3张。剧情会回顾之前带符还是参悟的选择。

护符只自动抵消山魈蓄力重击，每次消耗1张并立即保存；不抵消普通攻击，不在归山、重进、离线、重载时补充。整段见闻奖励只领取一次，复命状态和剩余护符随轮回保留。保留存档v3并为旧档补默认字段，恢复备份时两者整体恢复，不与当前状态叠加。

可调参数集中在`assets/balance.js`的`SHANXIAO`，状态推进是可测试的纯函数。角色与怪物原有HP、攻击、基础掉落、突破阈值、坊市与离线收益未改。

## 数值证据

`node scripts/monster-study.cjs`加载真实生产公式，与36626d3基线做同装备/境界/层数对照。每种情况20个随机种子，输出胜率、耗时和损血p10/中位数/p90；原始数据在[monster-study.json](monster-study.json)。这是首只敌人的受控战斗对照，不等同整周目评测。

- 全球境界序号S=4、第12层，纯挂机：20/20胜保持不变，中位损血204→122.4，击杀时间仍8.25秒。玩家有更长时间识别危险，收益未增加。
- 第6层初入者，纯挂机前后仍失败；拿到一次性的2张护符后，20/20可以过这一只敌人。不能据此推断无成本无限挂机。
- 受控第20层首领山魈样本（显式替换种类，非实际刷怪承诺），每秒2次手动点击：胜率4/20→20/20，中位损血979→540，通常完成1次破招。纯挂机仍失败，说明主动应对可以跨过这道障碍。
- 另外测量第7层、只在蓄力时出手的策略、以及真实分布中的第40层山魈首领，完整分位数见JSON。后续如扩充其他机制，应继续复用这套比较，而非只增加怪物数值。

## 美术与可靠性

`assets/art/shanxiao-stone-v2.webp`为本次原创生图的透明全身石甲山魈。第二版修正边缘余量，保留完整双手、双脚和举拳姿态；768×702，约149KiB。独立异步加载；失败、未完成加载或不支持WebP时使用原有程序化剪影。原生血条、姓名、蓄力提示与触摸区域不依赖图片，图片不会注册任何命中区域。

130项回归包含旧有Android pointerup→pointerleave事件序列，以及3次破招、自动伤害不算手动、同帧刷点击、低帧率、离线/弹窗/重进、护符消耗、复命幂等、旧档/老玩家满悟、恢复/轮回与图片失败。实际发布后的窄窗口绘制与输入验收另行记录；不把自动测试称为真机试玩。


## 窄窗口实测与补正

2026-10-06，云端Chromium普通窄窗口（约500px内容宽）以鼠标实际完成：保留存档续玩、领取离线收益、进入魔窟、滑动至见闻入口、推进解锁第6层、查看两种实际奖励预览、领取2张护符并返回「待破招」。该窗口原先显示Chromium错误9，经一次普通重新加载恢复；没有改浏览器安全设置或清理存档。

实测发现短窗口里的旧怪物姓名/血量跟随场景一起缩小，文字过小。补正将手机端怪物姓名、血量和蓄力提示放到原生HUD条，场景只缩放妖怪图片；360×480等尺寸仍维持≥14px的怪物姓名/血量。桌面保留原绘制方式，触控区域与Android修复均不变。完整新精灵与实际破招瞬间尚待一次专门的游戏画面检查；不把事件入口通过等同战斗真机验收。
