# 短屏战斗视野

## 触发条件和空间预算

可用高度不超过680 CSS px时采用紧凑布局，覆盖窄竖屏及宽度不超过1200px的横屏。HUD、字号与点击区域按CSS像素计算，画布仍铺满视口；只有场景插图等比缩放并裁在独立的战斗矩形内。横屏从560px宽起使用左战斗、右面板，控制栏至少296px。

玩家HUD高92px，保留境界、真实闯关进度、修为、气血、渡劫、剑侍秒伤与灵石。敌名和意图独占44px。竖屏战斗面板176px：44px导航，复用的进度/通知行，44px目标行，以及44px归山/返回闯关/见闻行。山门中的列表使用更高面板，避免第一项购买控件被裁在屏幕外。

## 操作与信息

- 魔窟面板的目标与退出操作固定可见。镜狐的预选/实际目标状态不改，温养范围和真实闯关进度仍分开显示。
- 修行、魔窟、功法、坊市保留直接入口；“详情”可打开全部六个面板和产率信息，并明确提供“返回战斗”。“见闻”继续进入既有两条剧情。
- 自动输出的秒伤持续显示在玩家HUD中。最窄横屏用较短的山魈提示保留倒计时、击剑次数和“按住破招”，没有缩小字体。
- toast复用已有进度行，单行显示最新提示，长消息尾部省略；不新增空白高度，不覆盖敌名、目标或退出按钮，不注册输入拦截层。保存异常仍有常驻HUD提示和设置里的备份入口。
- resize、方向切换，以及山门/战斗布局切换继续取消旧坐标上的未完成手势。插图位置与世界点击区域使用同一矩形；点击面板和HUD不会误算成世界攻击。

## 验证范围

182项生产脚本回归通过。新增13项检查覆盖五组尺寸、最窄右栏、原生字体和标签边界、矩形无重叠、真实pointer预选/详情返回/归山、toast位置与输入、旋转取消手势，以及相同随机种子下与长竖屏完全一致的战斗、镜狐任务与存档结果。原pointerdown/up/leave处理段、数值配置和美术文件逐字节保留。

旧测试仍执行拖动不购买、第二手指不提交、温养返回闯关和重复奖励检查；只让塔面板测试同时适配旧滚动控件与新固定控件。实际浏览器和Android真机验收需分别记录，不能用这些脚本断言代替。

## 原生Canvas薄条回归

实际844×390窗口发现：详情暂停在存活敌人画面后，控制栏和弹窗不再绘出。3 CSS px的敌人血条在缩放比大于1时不足3个逻辑单位，旧固定内边距产生负圆角半径，使浏览器中断该帧。依据[HTML Canvas规范](https://html.spec.whatwg.org/multipage/canvas.html#dom-context-2d-arcto)，负半径会触发IndexSizeError。

已将内边距限制为血条高度的四分之一，并在整个测试绘图上下文落实这一原生约束。新回归覆盖分数高度及844×390、1000×500、1180×480中存活敌人的详情打开、滚动、关闭、见闻往返，断言没有绘制异常。此修正只改变薄条几何，不改战斗状态或详情入口；实际浏览器仍须复验。
