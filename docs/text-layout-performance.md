# 有界文本换行缓存

## 诊断边界

本报告只检查源码与确定性渲染调用，不判断玩家设备的卡顿根因，也不把无绘图上下文中的耗时当作手机帧率。

源码与300帧计数显示：手机修行页每帧约46次`measureText`，猎妖弹窗256次，保险箱280次。弹窗为布局计算换行，实际绘字时又计算一遍；大部分段落逐帧没有变化。静态宣纸另有130个圆点与约520次确定性三角函数计算，仍值得以后在真实浏览器剖析，但本次未改变背景或美术。

应用代码每张图只建立一个图片对象；5秒代表样本发生1次约600字符的存档写入。特效按寿命删除，toast最多2条。没有发现普通运行中持续增长的主要数组；错误日志在持续异常时没有长度上限，但本次样本错误为0，不能据此称其为当前卡顿原因。

## 实现

- 只缓存换行结果，不缓存画面、数值、时间或游戏状态，不降低绘制频率。
- 键包含实际Canvas完整字体、完整文本、宽度，以及方向、字偶距、字体伸缩/变体、字距/词距、文字渲染方式和语言/方向继承参数。
- 最多128条；单段最多2048个UTF-16代码单元；键、文本和行数组另有32768单位的合计预算。超长文本仍按原算法绘制，只跳过缓存，不截断内容。
- 最近使用的布局保留，旧布局逐出；返回独立数组，调用方修改结果不会污染缓存。
- 字体ready、loading/loadingdone/loadingerror、resize以及绘图上下文切换都会清理缓存；字体集合仍在loading时不复用或新增缓存，避免部分字体先完成时留旧布局。动态资源值直接以完整新文本为键。

## 回归与可复现对照

运行`node scripts/check.cjs`：151项测试通过。新增覆盖容量/总量上限、超长文本、逐出顺序、字体家族/字号/字重、字距与语言参数、字体可用性改变、resize、240次弹窗切换、独立绘图上下文，以及缓存/实时重算的输出等价。

运行`node scripts/text-layout-study.cjs`可重建[JSON结果](text-layout-study.json)。对照使用同一生产换行算法，控制组关闭复用，同样初始绘制后每组计300帧；覆盖猎妖/保险箱/画卷/设置/功法、390→320→430→360宽度变化、动态资源数值、字体完成加载和字距变化。

- `measureText`：64,677→1,077，减少98.33%。
- 两组都执行16,380次文字绘制，文字内容/字体/坐标/样式序列哈希相同。
- 游戏状态相同；缓存峰值31条、4447预算单位，未达到上限。

这证明减少重复文字测量，并在这些场景中保持输出一致。Canvas测试使用近似字宽和空绘图实现，没有实测手机FPS、实际字体光栅化、GPU时间、图片解码或用户报告的卡顿。实际浏览器验证应与温养模式的窄窗口复核合并，记录真实结果后再评价体感。

字体集合的加载状态与整批完成事件依据[CSS Font Loading规范](https://drafts.csswg.org/css-font-loading/#font-face-set-events)实现。加载期间直接重算，完成后重新建立布局缓存。
